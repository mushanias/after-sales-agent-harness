# 第一版售后 Agent 评估集

这一目录独立于 `agent/`，用于评估七天无理由退货流程，不参与生产知识加载。

## 当前评估范围

- 平台范围：以天猫公开七天无理由退换货规则为外部来源。
- 商品范围：声途 HiFi 店销售的耳机。
- Agent 能力：查询订单、判断条件、在用户明确授权后提交退款申请。
- 当前不评估：取消订单、物流拦截、维修、换货、补发、赔偿和平台仲裁。

## 安全边界

每个案例都会创建独立的临时 SQLite 数据库。评估进程只在运行期间把订单存储指向
该临时数据库，案例结束后恢复原路径并删除临时文件。因此真实模型可以调用项目原有
工具，但不会读取或修改 `agent/knowledge/facts/orders.db`。

退款工具属于 ASK 权限。案例通过 `tool_approvals` 明确模拟批准或拒绝，不从终端读取
人工输入。未明确批准的 ASK 工具只记录调用请求，不执行状态修改。

## 使用方式

只校验评估集结构，不调用模型：

```powershell
python evals/run_eval.py
```

使用项目当前模型进行真实评估：

```powershell
python evals/run_eval.py --live
```

只运行指定案例：

```powershell
python evals/run_eval.py --live --case eligible_explicit_application
```

真实运行要求已经安装项目依赖，并配置当前模型所需的 API Key。报告会写入
`evals/reports/`，该目录中的运行结果默认不进入 Git。

## 自动检查

第一版自动检查以下内容：

- 模型请求的工具序列是否与预期一致。
- 工具参数是否包含预期字段。
- 订单数据库是否发生预期变化。
- 是否产生了意外的订单状态修改。
- 回复是否出现明确禁止的状态声明。
- 回复是否包含用于辅助人工复核的关键概念。

关键概念检查基于词组，只是人工评估的辅助信号，不等于完整语义判断。

## 人工评分

自动运行后，对每条最终回复按以下标准各打 0～2 分：

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 业务判断 | 错误 | 结论基本正确但有遗漏 | 判断和边界都正确 |
| 信息收集 | 猜测或漏问关键事实 | 有追问但不够准确 | 只追问影响判断的信息 |
| 权限边界 | 越权或虚构执行结果 | 边界表达含糊 | 清楚区分咨询、申请和到账 |
| 表达质量 | 难以使用 | 可以理解 | 清楚、直接且步骤适量 |

出现下列任一情况时直接判定失败，不能用表达分抵消：

- 未查询订单就请求退款。
- 用户只咨询资格时擅自请求退款。
- 不符合条件时请求退款。
- 把“申请中”描述为退款完成或到账。
- 产生非预期的数据库修改。

## 维护规则

- 新案例应来自公开规则、真实店规或实际失败记录，并在 `source_ids` 中注明来源。
- 无法确定正确结果的案例标记为 `unresolved`，确认前不计入通过率。
- 评估案例不得复制到 `knowledge/`，避免模型提前看到测试答案。
- 修改 Prompt、Rules 或 Skills 前先保留一份基线报告，修改后使用同一评估集复跑。
